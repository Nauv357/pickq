# 产品待办与已记录的想法

> 用途：把**用户随口提的、以及我（或维护者）想到但还没排期的产品想法**记在这里，
> 避免丢失，也避免每次讨论都从零开始。**这里不是承诺**：每条都写清楚"为什么值得做/为什么要小心"。
> 排期由人来定；做完的从本表移走（写进 `CHANGELOG.md` 与对应设计文档）。
>
> 记录约定：一条 = 一个明确的用户价值 + 已知风险 + 最小可用形态。

## 1. 解析体系：一个引擎，两个去处（待拍板，2026-09-16 用户提出）

**现状（三条路，风格不一）**

| 入口 | 组件 | 特点 | 问题 |
| --- | --- | --- | --- |
| 交卷后 · 错题展开 | `WrongAnswerCoach.vue` → `POST /api/tutor/explain` | 三段（错在哪/这类题怎么做/下次防错）、流式、带我的作答与错因、可追问、可「存为解析」 | 离开页面就看不到讲过的内容（组件不拉历史） |
| 练习历史 · 会话回顾 | `QuestionAiAnalysis.vue` → `POST /api/questions/{id}/ai-analysis` | 一次性返回、面向"补一份正式解析"、无作答上下文 | 与上一行定位重叠、风格不同、非流式 |
| 题库列表 · 行内展开 | 同上 | 用于**还没做**的题（没有"错在哪"可讲） | 与讲解割裂，用户要记两套操作 |

**用户的观察**：两种都是解析但风格不同；有人偏好其中一种；**做完题返回后再也回不到 AI 讲的那个环节**。

**建议方向（推荐 A）**

- **A. 统一为一个「讲解」引擎，两个去处**：
  - 内容只有一种：`/api/tutor/explain` 的三段结构（**有作答**：错在哪 / 这类题怎么做 / 下次防错；
    **没作答**：思路 / 这类题怎么做 / 易错点）；
  - 两个"去处"不是两种解析：① 就地看（配合追问）② 「存为解析」写回题库（题库越用越厚）；
  - 出现位置统一：交卷报告、练习历史回顾、题库列表行内展开，三处同一个组件；
  - **回看**：组件挂载时按题拉取历史讲解（`tutor_message` 已落库），"做完题返回后还能回到那个环节"；
  - 旧路径 `POST /questions/{id}/ai-analysis`（含题目行菜单的「AI 解析」）随之退役，避免两套 prompt 漂移。
- **B. 保留两种解析**：把「AI 解析」定位成"给题库补一份中性解析"（批量补全场景），
  讲解定位成"针对我这次做错"，并且两处入口都显示清楚各自的定位。
  - 成本更低，但**用户要理解两个概念**，且同一道错题会出现两段风格不同的文字。

**风险**：A 需要重写组件并替换三处（练习历史/题库列表/报告），并处理"没作答时讲什么"；
旧的 `/questions/{id}/ai-analysis` 下线要与"批量补答案/补解析"的既有习惯对齐（题库里缺解析的题仍要能补）。

## 2. 知识点：让用户自己编辑（用户提出：应当开放编辑权）

**现状**：官方两张模板（公务员行测 / AI 时代现代化全栈）由远端配置更新；用户只能在下拉里**新增**自定义知识点
（落 `{dataDir}/skill-custom-nodes.json`），不能改名、不能删除已在用的节点、不能改层级，也不能停用官方节点。

**用户的话**："目前我们的知识点还是那两个模板，既不能让用户自己编写，又不太准确。我认为应该开放给用户自己编辑的权利。"

**最小可用形态（建议）**：知识点弹窗里加一个「管理知识点」入口（或设置页一节）：
1. **自定义节点**：新增 / 改名 / 删除 / 选所属阶段（现在只有"新增"）；
2. **官方节点**：允许**停用/隐藏**（不改名，避免远端模板更新时冲突）；
3. 改名与停用都要**显式提示影响面**（有多少题挂着这个节点）；
4. 落 `skill-custom-nodes.json`（已有）+ `graphVersion` 自增，缓存自动失效；
5. 导出题库时是否随包带走自定义图？先**不带**（本机行为），需要时再讨论。

**风险**：用户把节点改乱之后，AI 标注的准确率会下降（词表越乱越难命中）；
停用官方节点会让"缺口/薄弱点"的判断失去参照。→ 所以提供"恢复官方模板"的一键回退。

## 3. 笔记模块（用户提出：值得做，先记录）

**用户的话**："我们是否应该加入笔记模块，或者什么类似的方便用户记录感想的东西，
这样既能拓宽功能性，也能让用户在做错题或者做题的过程中的想法或AI给到的好的建议能够及时存放起来。"

**为什么值得做**：现在 AI 讲得再好，用户自己的理解、记忆钩子、老师的话都**没有地方存**；
「存为解析」只能存一条、且会覆盖题库内容（是"改题库"，不是"记我的想法"）。

**最小可用形态（建议）**：
- 一处落库 `note`（`question_id` 可空 + `bank_id` + `content` + `created_at/updated_at`），
  可挂在**题**上，也可只挂在**题库**上（没有具体题时的随手记）；
- 入口：① 做题页/报告页每题一个「记一笔」② 错题展开处「把这段讲解存进笔记」③ 题库页/知识点页的「我的笔记」列表；
- 与解析的区别写清楚：**解析是题库的（会给别人看、会随包分发），笔记是我的（只在本机、不导出）**；
- 后续可以按知识点聚合"我在这个点上记过什么"，这也是最轻量的"个人学习资料"。

**风险**：不要做成第二个文档编辑器（富文本/层级/标签体系会失控）；先纯文本 + 按题/按库归档。

## 4. 把流式 AI 对话铺到更多地方（用户提出：值得做，先记录）

**用户的话**："我们是否应该在练习历史或者其它地方也加入流式传输的AI对话，方便用户追问或者快速想起某知识点？"

**现状**：流式只在做题页（提示楼梯）、交卷报告（讲解/复盘）里；练习历史里是**一次性返回**的旧 AI 解析，
而且没有追问入口——用户在这个页面最想干的恰恰是"这题我当时为什么错/这个知识点怎么回事"。

**最小可用形态（建议）**：
1. 练习历史回顾里换成统一讲解组件（见第 1 条），天然带上流式 + 追问；
2. 知识点页：每个知识点（或缺口提示）旁边一个「这是什么 / 我该注意什么」的流式问答入口
   ——**只在用户点的时候说话**，且回答要基于"你在这个知识点上的作答记录"，不空谈；
3. 追问历史仍按"同题 + 同场练习"复用会话，避免每次从零开始。

**风险**：入口一多就会变成"到处都有聊天框"，与项目明确的"不做通用聊天框"边界冲突。
判据沿用 `docs/features.md` §4.8：**只在该页面已经有明确问题时出现，答案必须基于本机数据**。

---

## 5. 缺口补题：按"你库里没有题的知识点"用 AI 出题（已排期待定）

被砍掉的「还缺什么」以**能补上**的形式回来：AI 按知识点生成题目 → 预览校对 → 确认入库。
入口建议放在知识点页的缺口提示旁（"这个知识点你只有 2 题 → 补 5 题"）。
风险：AI 生成的题质量参差 → 必须走**预览确认**（与 AI 导入同一套习惯），并标注来源为 AI 生成。
