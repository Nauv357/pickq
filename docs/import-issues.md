# 导入问题记录（海外试卷测试）

> 状态：**仅记录，暂不修复**。当前产品优先服务国内考公/考研场景；
> 以下问题来自导入一张国外 SAT 试卷（PDF）的实测，未来做海外支持或通用解析时再处理。

记录时间：2026-09（v0.1.8 时代）

---

## 1. PDF 中的表格：以 Markdown 写法输出，但渲染出来不是表格

- 现象：PDF 里的表格被识别为表格内容，导出/展示时用的是 Markdown 表格写法（`| --- |`），
  但题目内容渲染出来并不是表格，仍是没被解析的 Markdown 原文。
- 判断：PDF 表格**不是图片**，用表格形式输出本身是正确处理；
  问题出在题面/解析的富文本渲染层不支持表格（或未渲染 Markdown 表格语法）。
- 排查方向：题目内容渲染器（rich-text / markdown 渲染）的表格支持。

## 2. 选项数量错认：4 个选项被识别成 8 个（其中 4 个是空的）

- 现象：明明只有 4 个选项的题，导入后出现 8 个选项，多出的 4 个为空。
- 可能原因：对海外试卷的选项排版（如两栏排布、行内连续选项、字母后紧跟内容无换行等）
  解析/切分逻辑判断错误，把每栏或每个字母都当成了一个选项起点。
- 排查方向：AI 结构化抽取与后处理对选项边界的判定。

## 3. 下划线标记的长段落（定位段）无法同款导入

- 现象：英语试卷常见"给某段落加下划线，用于定位特殊题目"的版式；
  录题时无法还原同样的下划线长段落。
- 本质：格式保真问题——段落级下划线（underline）样式没有随题目内容一起保留/还原。
- 排查方向：题目内容的格式模型是否支持段落级下划线，导出/导入是否保真。

## 4. 卷内题号分段：题号错乱导致漏题（较严重）

- 现象：SAT 试卷分多个科目/Part，题号在每个 Part 内重新编号（各 Part 都有 1..N）。
  导入时按题号顺序处理，导致：第一 Part 前 13 题正常 → 第 14 题跳到第二 Part 的第 14 题
  → 第 15 题又跳回第一 Part …第 17 题又跳到第二 Part 的 17 题，18 题再跳回……
- 结果：试卷实际题量远大于录入量，最终只录入了 33 题（第一 Part 共 33 题）——
  后续 Part 的题与前面 Part 同号时被当作重复/覆盖处理了。
- 排查方向：跨 Part 的题号冲突识别（题号不能作为唯一顺序键）、按 Part/Section 分组后再处理。

## 5. 从 PDF 提取的图片大多是纯黑图（可能严重）

- 现象：试卷中的图/图标提取后大多变成纯黑图片。
- 推测：这些图形是 PDF 里的矢量绘制（工具画的示意图/图标），当前提取方式把它们
  渲染成了黑色块。
- 可能方向：接入 MinerU（PDF 解析引擎）等更完整的版面解析方案来解决。

## 6. Excel / PPT 里的图片不参与导入（2026-09-13 记录 + 当天修复 MinerU 路径）

- 现象：`.xlsx` / `.pptx` 按行列、逐页抽取**文字**交给模型，但文件里插入的图片（题干配图、
  图形推理的选项图、图表、公式截图、纯图片题）不会被提取——含图题会缺图，
  纯图片题（题干与选项都在图里）只能得到标题文字或空内容。
- 与 PDF 的差别（为什么 PDF 可以）：PDF 走 PDFBox，能拿到每张内嵌图的**页面与坐标**
  （`ExtractedImage(pageNo, sortX, sortY, …)`），于是可以在页文本里插入 `[图片N]` 锚点，
  分块时按锚点/页归属取图；docx 同理（POI 按 body 元素顺序取图并就地插锚点）。

### 6.1 MinerU 路径：已修复（勾选「MinerU 增强」时可提取 Office 内嵌图）

实测结论（用 `D:\PickQ\test-cases-20260913\` 的两个用例跑真实 MinerU vlm）：

- MinerU **确实**会抽出 Office 文档里的图片：pptx 8 页 → 6 张图（`content_list_v2` 里 6 个
  `image` 条目）；xlsx 2 个工作表 → 6 张图（**没有** `image` 条目，只在 `table` 的单元格 HTML 里
  写 `<img src="images/<hash>.jpg">`，共 10 处引用）。
- 而我们的重建层当时一张都没拿到（`imports/<jobId>/images/` 为空）。三个独立缺陷，已全部修掉：
  1. **无 bbox 的图被丢弃**：PDF 的条目带 `bbox`，Office 的条目只有 `type`+`content`；
     图链结算里 `bbox == null` 写的是 `continue`（注释本意是"单张输出、不入链合并"）→ 整批丢。
     现按出现顺序逐张输出（`MineruRebuildOfficeImageTest.keepsImagesWithoutBbox` 锁住）。
  2. **jpg 被当成 png**：MinerU 的图是 jpg，管道契约是 PNG（`{N}.png` + `ImageData("image/png")`），
     无 bbox 分支少了 `toPngBytes` 转换 → 现在统一转换（顺带验证"路径→图片"不错位）。
  3. **路径被折行**：MinerU 会把超长 hash 折行写进 HTML（JSON 里是 `\n` 转义），解析后路径中间
     真的带一个换行 → 查不到文件（10 处引用里 3 处中招）。现统一 `normalizeImgPath` 去空白。
  4. **表格内嵌图没被识别**（xlsx 专用）：`table` 的 HTML 里 `<img>` 就地换成 `[图片N]`，
     锚点落在**所在单元格/行**——比 PPT（无坐标，只能追加在页末）归属更准。
- 仍存在的边界：老 `.doc` 的图片仍不提取（见 6.2）。

### 6.2 本地文本路径（不勾 MinerU）：已实现（2026-09-13 第二轮）

用户口径：**MinerU 只是"识别失效时的最终手段"，质量与成本都不该当默认路径——能直接取原图就走老路子。**
于是按 6.1 的思路把"直接从文件里取图"补齐（与 docx 同一套机制：`[图片N]` 写进文本 + `extractedImages` 带图
+ `pageTexts` 留空，交给既有的 `marksInText → chatChunked` 按标记取图），**不开 MinerU 也能拿到 PPT / Excel 的图**：

- **PPT / PPTX**（`XSLFPictureShape`）：逐页取图，按形状顺序就地插标记（标记位置 = 图在这一页的位置），
  **组合形状递归**；同一张图片文件在多页复用（页眉 logo、背景图）只登记一份，其余页仍留一个指向它的标记
  ——标记同时是"这一页有图"的信号，**整页只有图的幻灯片不会被当作空页丢掉**（纯图片题）。
- **Excel / XLSX / XLS**（`XSSFPicture` / `HSSFPicture`）：`ClientAnchor.getRow1()` 就是"这张图放在哪一行"，
  标记插在**该行文本之后**（比按坐标猜位置可靠）；同一张图锚在两行 → 两行各出一份（Excel 的图是"放在某行上"，
  不是文档级一次）；锚在空行/合并单元格的浮动图附在工作表末尾，宁可位置粗也不丢图。
- 图片统一走 `officePictureToPng`：栅格图缩放转 PNG，WMF/EMF（矢量）用 POI 渲染为白底 PNG；
  解不开的（WDP、损坏文件）跳过并给 warning（"有 N 张图片无法解码"）。

实测（真实用例 `D:\PickQ\test-cases-20260913\`，**不开 MinerU**）：

| 文件 | 提取图片 | 说明 |
| --- | --- | --- |
| 含图片题型的课件.pptx | 6 张 | 8 页；第 3 页"整页一张图"的纯图片题保留 |
| 含图片的题库表格.xlsx | 10 张 | 两个工作表；每张图跟在它所锚定的那一行后面 |

端到端（真 jar + 假模型端点，只看实际请求体）：PPT 那次请求带 `images=6 markers=1..6`；
Excel 那次 `images=10 markers=1..10`，且分块后**每块只带自己标记编号对应的图**（不会把 10 张图塞进每一块）。

仍存在的边界：
1. **老 `.doc`** 的图片仍不提取（HWPF 取图要走 `PicturesTable` + 字符偏移，性价比最低，暂不做）。
2. WMF/EMF 渲染失败的图会跳过并提示（矢量渲染不是 100% 覆盖）。
3. 备选方案（用户建议、暂不做）：**后端把文档"分页截图"成纯图片再走视觉路径**。PPT 需要 Office/LibreOffice
   之类渲染器（纯 Java 侧没有可靠组件），Excel 成本更高；Android 端或无 Office 环境会更复杂——
   **优先直接从文件取原图**（本条已落地），截图这条路继续留作最后手段。

  它能救扫描件/图片型文档，但要走云端、花额度，结果质量也低于"直接取原文/原图"；
  凡本地能确定性拿到的内容都不应交给它。因此每遇到一类"缺内容"，先问"能不能本地直接取"，
  其次才是 MinerU，最后才是截图渲染那条路。
- 这些与"表格渲染""选项边界""格式保真""分卷题号""矢量图提取"相关，
  未来若做通用解析/海外支持，可优先按严重程度处理：4/5 → 2 → 1 → 3。
