# 题目分类体系与知识点审阅界面设计（2026-09-15）

> 背景：用户实测后提出三个问题——① 同时存在「知识点 tag / 主题 / 分类」三个字段，
> 不知道该填哪个、也说不清三者区别；② 知识点只能由 AI 给，改不了；③ 在知识点界面里
> 要改标签必须跳到题目编辑器，"AI 标完就应该在当前界面检查并修正"。
> 本文是**判断与设计**，不是实现记录；实现分 P0/P1/P2 三步，见 §8。

> **已实施（2026-09-15，用户拍板：字段 A / 界面 P0 / 归属 A）**
> - §4 字段收敛：两维度（归属 + 知识点），「分类」下线，一次性合并动作已上；AI 导入提示词只输出归属；
> - §5.2 的 P0 部分：就地改标签、状态筛选器、就地展开题干、批量、详情可选、缺口并入知识点筛选；
> - 权威实现见 `CHANGELOG.md` 的 `[Unreleased]` 与 `docs/features.md` §4.5；
> - P1（独立页面 + 右侧知识点树）与 P2 剩余项（归属的批量编辑入口）尚未做。

## 0. 结论速览

1. **字段收敛成两个维度，一个维度只留一个字段**：
   - **归属**（沿用 DB 列 `topic`，界面文案「试卷 / 章节」）＝这题**从哪来**，自由文本，导入时按文档结构自动填；
   - **知识点**（技能图节点，多值）＝这题**考什么**，受控词表，AI 提议 + 人拍板；
   - **「分类」从所有界面下线**：DB 列与包格式保留（兼容旧数据与广场作品），并在题库页提供一次性合并动作。
2. **知识点审阅从"必须跳编辑器才能改"改成"就地改"**：行内多选下拉直接落库；
   「打开题目」降级为"看详情"的次要入口。
3. 落地顺序：**P0 先做"就地改 + 状态筛选 + 批量"**（已做），P1 再上独立页面与知识点树联动。

## 1. 现状盘点（代码事实，不是印象）

| 字段 | 谁填 | 出现在哪些界面 | 实际承担的作用 |
| --- | --- | --- | --- |
| `topic` 主题 | 编辑器自由文本；AI 导入（可选） | 题目行内的小标签、练习「按分类」筛选 | 练习/导出范围筛选；**AI 打标签的分组键（首选）** |
| `category` 分类 | 编辑器自由文本；AI 导入（可选） | 题目列表筛选下拉、练习筛选、打印页筛选 | 练习/打印/导出范围筛选；**AI 打标签的次选分组键** |
| `volume` 册数 | 编辑器手填 | 只在编辑器里 | 几乎没有用途（AI 导入提示词里根本没这个字段，永远默认 1） |
| 知识点（技能图节点） | AI 提议 + 人工确认；编辑器可改 | 「知识点」弹窗、题目编辑器 | 学习路线、掌握度门控、覆盖缺口（**唯一受控、唯一机器要用**） |

**已经能看出来的矛盾（都来自代码）**：

1. 题目列表行**显示的是 `topic`**（`q-topic` 小标签），但筛选下拉**只有 `category`** —— 用户看得见的值筛不了，能筛的值看不见。
2. 打印页只暴露「分类」；练习的「按分类」模式却同时给「主题」和「分类」两个多选。
3. 编辑器的占位符暗示了两者不同的意图：主题「如：交通信号」（内容）、分类「如：基础题」（难度/用途），
   但**没有任何文案解释**这个区别。
4. AI 导入提示词只写 `topic: 主题（可选） category: 分类（可选）`，**不定义含义** —— 模型只能自由发挥。
   结果就是你库里 212 题只有 3 题填了 topic、0 题填了 category，而且那 3 个值大概率彼此不一致。
5. 知识点落地后，三个字段都在回答"这题是什么"，而其中只有一个（知识点）是有词表、能算掌握度的。

## 2. 用户视角的问题诊断

| 用户的原话/困惑 | 真实成因 |
| --- | --- |
| 「不知道该填哪个」 | 三个字段没有分工说明；两个自由文本字段的语义还重叠 |
| 「不知道什么是知识点、什么是主题、分类」 | 知识点是**受控词表**（技能图），另两个是**自由文本**；这个本质区别在界面上完全看不出来 |
| 「AI 判断错了没有改正渠道」 | 改标签的唯一入口在题目编辑器深处（且这一栏上轮才修好加载），知识点界面里只能"跳过去" |
| 「在当前界面就改了，为什么要跳转」 | 审阅流程被设计成"看弹窗 → 跳编辑器 → 回来"，中间丢了上下文（列表滚动位置、筛选、勾选） |

**一句话**：我们其实只需要回答两个问题——
**「这题从哪来」（组织）** 和 **「这题考什么」（语义）**。
第三个字段（分类）回答不了任何新问题，只是把第一个问题答了两遍。

## 3. 设计原则

1. **一个维度只留一个字段。** 能删就删；删不掉（兼容）也必须让它在界面上消失。
2. **组织维度自由文本、语义维度受控词表。** 不要出现"两套都是自由文本"或"两套都是词表"。
3. **机器只提议，人拍板。** 人改过的标签是权威，永不被 AI 覆盖（现有规则保留）。
4. **标签不阻塞刷题。** 没标签的题照常进练习与复习调度（现有规则保留）。
5. **在哪里发现问题，就在哪里改。** 审阅界面必须能就地改标签；跳转只能是"想看更多细节"的可选动作。
6. **界面上的每个数字都要能点出对应的清单。** 统计与清单必须同一口径（上轮教训）。

## 4. 最终字段模型

| 维度 | 回答的问题 | 取值 | 谁填 | 用在 | 界面位置 |
| --- | --- | --- | --- | --- | --- |
| **归属**（DB `topic`，文案「试卷 / 章节」） | 这题**从哪来**（哪套卷、哪一章、哪一节） | 自由文本，题库内建议复用已有值 | 导入时按文档结构自动填（卷标题/章标题）；用户可改 | 找题筛选、打印组卷、导出子集、练习范围、AI 分组键 | 题目列表筛选 + 行内标签；编辑器一个输入框 |
| **知识点**（技能图节点，多值） | 这题**考什么** | **受控词表**（阶段 → 节点） | AI 提议 → 用户确认/就地改 | 学习路线、掌握度门控、覆盖缺口、复习调度 | 知识点审阅页；编辑器一个多选框 |
| ~~分类~~ `category` | —— | 保留列与包格式 | 不再由任何界面写入 | 仅兼容 | **下线**（不出现） |
| ~~册数~~ `volume` | —— | 保留列 | 不再出现在编辑器主流程 | 兼容 | **下线**（并入归属描述） |

**改名/迁移策略（成本最低的做法）**

- **不改 DB 列名**（`topic` 继续用）：只改界面文案、提示词与默认行为，零数据迁移风险。
- 「分类」不清空、不删除：导出的内容包照旧携带；旧题库文件导入后这些值仍在库里（只读）。
- 提供一个显式动作（放在题库详情页「…」菜单里）：**「把「分类」并入「试卷/章节」」**——
  仅在 `topic` 为空时用 `category` 填充，随后界面不再展示分类。用户看得见、可反悔（有备份/导出）。
- AI 导入提示词改为：`topic: 所属试卷/章节（按原文的卷/章标题填，没有就留空）`，**删除 `category`**。
- 练习模式的「按分类」改名为「按试卷/章节」；打印页筛选同步改名并改为按 `topic`。

## 5. 知识点审阅界面

### 5.1 现在的界面为什么不合用

| 现状 | 问题 |
| --- | --- |
| 弹窗（`min(94vw,900px)`，列表区 `max-height:44vh`） | 审阅 100+ 题是**持续几十秒到几分钟的任务**，弹窗里有小滚动区，题干看不全、题库列表被遮住 |
| 三个页签：待确认 / 未匹配 / 覆盖地图 | 用户脑子里只有一件事："AI 标得对不对"。"待确认"和"未匹配"是**同一个动作的两个状态**，分页签反而要来回切 |
| 改标签只能「打开题目」跳编辑器 | 改一个下拉要跳页、丢失列表上下文（滚动位置、筛选、勾选）——最影响效率的一条 |
| 行内只有题号 + 一行截断题干 | 判断题干要看详情；选项/解析/图片都看不到 |
| 覆盖地图与清单分离 | 看到"增长类只有 2 题"想直接看这 2 题，做不到 |
| 没有批量与搜索 | 172 题里想"只看某知识点"或"搜关键词"都不行 |

### 5.2 目标形态：独立页面（题库详情页 →「知识点」）

```
┌────────────────────────────────────────────────────────────────────────────┐
│ ← 返回题库    公务员行测（通用） ▾     覆盖 61%  ▮▮▮▮▮▮▯▯▯▯     [分析并标注] │
│ 状态： (全部 172) (待确认 12) (未匹配 26) (已确认 100)      搜索题干…  [筛选▾] │
├──────────────────────────────────────────┬─────────────────────────────────┤
│ 题目清单（标签就地可改）                  │ 知识点（技能图）                │
│ ┌──────────────────────────────────────┐ │ 资料分析            5/6 已覆盖  │
│ │ ☐ 12  [资料分析·增长 ✕][+ 添加]  AI .91│ │  ▸ 增长类           24 题  ✓    │
│ │   2019—2023 年该省 GDP 年均增长率…    │ │  ▸ 比重与倍数        8 题  ✓    │
│ │   [确认] [丢弃建议] [展开题干] [详情] │ │  ▸ 平均数与指数      2 题  ⚠题太少│
│ ├──────────────────────────────────────┤ │  ▸ 速算技巧          0 题  ⚠你没有│
│ │ ☐ 13  [选择这道题的知识点…]     未匹配│ │ 数量关系            1/6         │
│ │   依次填入下列横线处的词语…           │ │  …                              │
│ │   [指定知识点] [让 AI 再试] [详情]    │ │                                 │
│ └──────────────────────────────────────┘ │                                 │
├──────────────────────────────────────────┴─────────────────────────────────┤
│ 已选 3 题： [设为知识点 ▾] [确认] [丢弃建议] [清空选择]                     │
└────────────────────────────────────────────────────────────────────────────┘
```

**布局理由（对着用户习惯逐条）**

- **左边是"待处理的题"，右边是"知识点的地图"**：审阅时视线只在两处——题目本身、以及"这条路线还缺什么"。
- **默认停在最需要处理的状态**（有待确认 → 待确认；没有 → 未匹配；都没有 → 已确认列表），
  而不是先给一张统计表让人自己找入口。
- **状态不是页签而是筛选器**：四个数字都可点击，点哪个筛哪个，且随时可叠加"知识点/题型/关键词"，
  再也不会出现"两个页签里各有一半同类问题"。
- **标签就在行内**：多选下拉（按阶段分组、可搜索），改完立刻生效并标记为「你标注的」；
  AI 建议未确认时显示把握分与 [确认] / [丢弃建议]，人在原地完成"接受或修正"。
- **题干行内展开**：点一下就地展开选项、答案、解析（必要时图片），
  **「详情」才是跳题目编辑器**（看完整编辑能力）——跳转从"必须"变成"可选"。
- **右侧知识点树可点选筛选**：点「增长类」= 只看这个知识点的题；同时它本身就是"缺口地图"
  （题量 / 覆盖率 / "你没有这个知识点的题" / "题太少"）。
- **底部批量条**：勾选多题后统一设知识点 / 确认 / 丢弃；支持"全选本页"。
- **顶部只留两个动作**：切换技能图、分析并标注（按批推进，进度就地显示）。

### 5.3 状态与口径（沿用上一轮修好的口径，不再新增概念）

- 四个状态计数**互不重叠**：`已确认 + 待确认 + 未匹配 = 总题数`；「可用于判定掌握」另列（已确认 或 AI ≥ 0.8）。
- 每个数字都必须等于按该状态查出来的清单条数（已有接口 `GET /banks/{id}/skills/questions?status=`）。
- "未匹配"的定义固定为：**没有任何可用标签**（AI 没给、或给的节点不在词表里被丢弃）。

### 5.4 空态与首次使用

- 没配 AI Key：说明"去设置里填 Key 就能自动标注"，并允许**手动逐题指定**（可用）。
- 没有题目：直接给"去添加题目 / 导入题库"。
- 全部未匹配（AI 一个都没给）：提示"可能技能图不合适，换一张或告诉我你的题库范围"。

### 5.5 与题目编辑器的关系

- 编辑器里的「知识点」多选保留（它是"我在看这题内容时顺手改"的入口）；
- 从审阅界面点「详情」进来时，该栏仍然滚到视野中间并高亮（上一轮已做），
  但**它不再是唯一的修改入口**。

---

## 6. 与学习路径的衔接（不变）

- 门控只认「已确认」或「AI 置信度 ≥ 0.8」（`GATE_MIN_CONFIDENCE`）；
- 覆盖缺口 = 技能图上题量为 0 或 <3 的节点（`evidenceEnough`）；
- 标签随包分发（作者确认过的），供广场质量分与共享路线使用；
- **归属 `topic` 对学习路径没有影响**，它只服务人的组织需求与 AI 分组的效率优化。

---

## 7. 明确不做

- **不做多级分类树**：层级信息已经在技能图的「阶段 → 节点」里，再加一层分类树必然打架。
- **不做"必须先补全归属才能标注"**：会挡住所有人（真实数据里 98.6% 的题都没有归属），而标注并不依赖它。
- **不做用户自定义技能图编辑**：阶段 4 再说（当前只做远端模板更新）。
- **不删除 `category` 列与包字段**：破坏旧包兼容得不偿失。

## 8. 分阶段落地

### P0（已实施：解决"改不了、要跳转"的阻塞，不动导航结构）

1. ✅ 待确认与未匹配**合并成一个清单**，用顶部的状态筛选器（可点击的数字）切换；
2. ✅ **行内就地改标签**：多选下拉（按阶段分组）+「确认 / 丢弃建议 / 看题干 / 详情」；
3. ✅ 行内**展开题干**（选项/答案/解析）；
4. ✅ 勾选 + 批量：设为知识点 / 确认 / 丢弃；
5. ✅ 「详情」保留跳转编辑器（可选，不强制）；
6. ✅ 覆盖地图的缺口信息并入**知识点筛选下拉**（下拉里带题量、"你没有题"直接标出 + 一行缺口提示），
   不再需要一个单独的页签。

### P1（独立页面）

7. 从弹窗升级为 `/banks/:id/tags` 页面，左侧清单 + 右侧知识点树（点节点筛题）；
8. 清单支持关键词、题型、归属筛选。

### P2（字段收敛）

9. ✅ 编辑器：删除「分类」输入框，`volume` 移出主流程；「主题」改名「试卷 / 章节」；
10. ✅ 列表筛选、练习筛选、打印筛选统一改为「试卷 / 章节」（按 `topic`）；
11. ✅ AI 导入提示词：只输出 `topic`（按原文卷/章标题），删除 `category`；
12. ✅ 一次性迁移动作：「把「分类」并入「试卷 / 章节」」（题库页在有遗留分类值时出现，处理完自动消失）。

**尚未做（留在 P1/P2 的尾巴）**

- 归属的**批量编辑入口**（在题目列表勾选若干题统一设置「试卷 / 章节」）——AI 导入会按文档结构填，
  但纯手写的题库可能想批量补；
- 独立页面与右侧知识点树（P1）。

## 9. 验收（都可自动化）

- **就地改标签**：在审阅清单里改一题的标签 → `question_skill` 出现 `source=user, confirmed=1`，界面状态与计数同步；
- **未匹配可补**：从"未匹配"直接指定知识点 → 该题从未匹配计数里移出，已确认计数 +1，三段仍然相加 = 总题数；
- **不跳页可完成审阅**：整轮审阅（确认 / 改标签 / 丢弃 / 补标）**不产生任何路由跳转**也能完成；
- **批量**：勾选若干题统一设知识点 → 每题一条 `source=user` 落库；
- **字段收敛**：全站界面不再出现「分类」字样（除兼容提示与迁移动作）；任何界面都不同时出现"主题/分类"两个自由文本输入；
- 口径对账断言（概览数字 = 清单条数）继续保留在 `e2e-skills-live.mjs`。
