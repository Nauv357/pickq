# 官网与题库广场改版需求

> 状态：**设计稿**（2026-09-14）。依据：用户反馈 + 对现网的诊断。与 `docs/learning-path-design.md` §10 配套。
> 范围：`web/`（Nuxt 3 官网 + 题库广场）。客户端应用内界面不在本文（见 `docs/design-ui.md`）。

---

## 0. 问题诊断（为什么现在不好用）

1. **两种页面共用一套版式**：官网首页是**品牌叙事页**（文学向、大留白、情绪优先），题库广场是**工具目录页**（任务优先、信息密集）。共用视觉的结果是广场"每个模块界限不清、抓不住重点"。
2. **广场的任务没被当任务对待**。用户来广场只做三件事：**找到能用的题库 → 下载/导入 → 开始刷**。当前版式把这三件事埋在了叙事性排版里。
3. **缺少可判断的质量信号**。用户看不出"这份题库值不值得下"（有多少题、有没有解析、来源是哪年真题、标签完整不完整）。
4. **筛选与排序过弱**。只有关键词与"最新"，没有学段/科目/题数/含解析/质量分。
5. **列表密度过低**。卡片过大，一屏看到 2–3 个作品，浏览效率差。

**设计原则（两条，冲突时以此为准）**

- **A. 叙事归首页，工具归广场**：两者共享设计令牌（配色/字体/圆角），但**不共享版式**。
- **B. 一切为"快速判断 + 带走"让路**：每个作品卡片必须在一眼之内回答"多少题、什么来源、有没有解析、怎么拿走"。

## 1. 广场列表页（`web/pages/packs/index.vue`）

### 1.1 信息架构（自上而下）

```
[搜索框]  [筛选条]  [排序]
─────────────────────────────
结果计数 + 当前筛选的可清除标签
─────────────────────────────
列表（行式，不是大卡片）
  标题（1 行，超长省略）
  一句话描述（1 行）
  元信息：题数 · 版本 · 作者 · 更新时间 · 来源
  质量信号：标签完整 92% · 含解析 · 2024 国考
  [下载]（主）  [详情]（次）  [收藏]
─────────────────────────────
分页
```

### 1.2 硬指标（可验收）

| 项 | 要求 |
| --- | --- |
| 列表密度 | 1440×900 下**一屏 ≥6 行** |
| 首屏动作 | 不用滚动就能看到**至少一个下载按钮** |
| 元信息层级 | 题数与来源**加粗/加深**，作者与时间弱化 |
| 筛选 | 学段/科目/题型/题数区间/含解析/标签覆盖率/更新时间；筛选状态可一键清除 |
| 排序 | 最新 / 下载最多 / **质量分** |
| 空结果 | 给"换关键词"建议 + 收录指引（不是空白页） |
| 移动端 | 单列，筛选折叠为抽屉 |

## 2. 作品详情页（`web/pages/packs/[packageKey].vue`）

### 2.1 首屏（必须回答四个问题）

1. 这是什么题库？（标题 + 一句话）
2. 值不值得下？（质量信号：标签完整度 / 含解析 / 来源年份 / 题数）
3. 怎么拿走？（**下载 .zip** 主按钮 + "导入到应用"的说明）
4. 是最新的吗？（版本历史入口）

### 2.2 主体结构

```
简介（作者描述）
内容概览：题数 / 分类分布（后续：技能节点分布）
版本历史：每行 版本 · 时间 · 说明 · [下载此版本]
评论（现有）
举报入口（现有）
```

### 2.3 下载体验（已实现部分，保持）

- 下载按钮下方保留："已在浏览器开始下载…若长时间没有进度，可复制直链/重新下载（支持断点续传）"。
- 文件后缀以作者上传的为准（新包 `.zip`，旧包 `.tiku`），**不要统一改写**。

## 3. 质量信号（排序与筛选的核心）

### 3.1 计算（服务端，`web/server/utils/`）

```
quality = 0.35 × 标签覆盖率   （有技能标签的题 / 总题数）
        + 0.25 × 解析完整度   （有解析的题 / 总题数）
        + 0.20 × 答案完整度   （有答案的题 / 总题数）
        + 0.10 × 来源标注     （来源/年份/卷别是否填）
        + 0.10 × (1 − 疑似重复率)
```

- 全部字段**可从内容包里确定性算出**（`package.json`），不依赖作者自填的"质量声明"（防作弊）。
- 首次计算在上传时完成，落库到 `packs` 表新增列（`quality_score` / `tag_coverage` / `analysis_coverage`），旧行回填为 NULL 并显示"未评估"。

### 3.2 展示口径（用户能懂，不暴露公式）

| 内部 | 展示 |
| --- | --- |
| 标签覆盖 ≥90% | 标签完整 |
| 解析覆盖 ≥80% | 含解析 |
| 来源已填 | 来源：2024 国考 |
| quality ≥0.8 | 质量优选（列表页可加一个小标记） |

## 4. 首页（`web/pages/index.vue`）要补的东西

保留现有叙事气质，但把"看得见的效果"和"能找到入口"补上：

1. **首屏加 30 秒演示位**：一张"导入一份 PDF → 变成能刷的题库"的对比图/GIF（胜过十行文案）。
2. **锚点导航**：下载 / 功能 / 常见问题 / 广场（当前页面过长但无导航）。
3. **三张真实截图**：题库列表、做题界面、错题追问（新功能上线后替换）。
4. **常见问题**（把支持成本前移）：题库从哪来？要不要付费？（不需要，用自己的 API Key）/ 数据在哪？（本机）/ 支持哪些格式？
5. **下载区**：安装包 + 便携版 + 版本号 + 更新日期（已实现，保持）。

| 广场侧 | 依赖 |
| --- | --- |

## 6. 明确不做

- 不做社区动态流 / 关注时间线（已有"关注作者"够用）；
- 不做在线做题（做题在客户端，广场只负责分发）；
- 不在广场做 AI 生成题（生成题属于客户端本地能力）；
- 不为广场单独造一套视觉语言（共享令牌，只改版式与信息密度）。

## 7. 验收清单

- [ ] 广场一屏 ≥6 行，首屏可见下载按钮
- [ ] 筛选条 6 个维度全部生效且状态可清除
- [ ] 排序含"质量分"，质量分可在详情页用自然语言解释
- [ ] 列表与详情页都能看到质量信号
- [ ] 下载有进度、可续传、直链可复制（已实现，回归验证）
- [ ] 移动端单列可用，筛选进抽屉
- [ ] 首页有演示位、锚点导航、常见问题
- [ ] 空结果页有建议与收录指引
