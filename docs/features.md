# 功能清单与业务规则（拾题 PickQ）

> 面向两类读者：想了解"这东西到底能干什么"的用户，以及准备改代码 / 做移动端的贡献者。
> 每节末尾的「规则」是从**代码里提取**的确定性行为，不是设想。代码依据以文件名为准。

## 0. 一句话定位

拾题是一个**本地优先（local-first）的题库工具**：你自己录题或从文档用 AI 批量导入，做题记录、错题本、复习计划、备份全部存在本机；需要分享时，把题库导出成 `.zip` 题库文件（就是个标准 zip，可直接解压查看图片与题目；旧版的 `.tiku` 文件同样能导入），或登录账号发布到官网广场供他人下载。

- 桌面端：Windows 桌面应用（Tauri 壳 + 内置 JRE + 本地 Spring Boot 服务 + Vue 3 界面），**数据不出本机**，唯一的外部调用是你自己配置的 AI 接口。
- 官网/广场（pickq.cn）：账号、题库广场、评论、关注、后台管理（此部分不开源，`web/` 不入库）。
- 移动端：规划中，见 `docs/design-mobile.md`。

## 2. 题库管理

- 题库字段：名称、描述、作者、来源/出处、分类、`packageKey`（包唯一标识）、版本、复习开关（`review_enabled`）。
- 导入方式：JSON、题库压缩包（`.zip`；旧版 `.tiku` 同格式）、AI 导入；导出方式：JSON、`.zip` 题库压缩包（v2 容器）。
- 导入反馈（2026-09-14 修）：导入是同步接口，含图题库在慢机器上要几秒到几十秒，所以**导入期间给出全屏进度**
  （「正在导入题库…（已用 N 秒）」+ 主按钮变成"正在导入题库…"并禁用），且**不设客户端超时**
  （全局 axios 15s 会先中止请求，而后端仍在跑 → 用户看到"点了没反应"，刷新才发现已导入）。
- 合并：把另一个题库的题目并入当前题库（`POST /api/banks/merge`）。
- 选题复制：按条件从题库挑选题目复制到另一个题库（`selection-copy`）。

**规则**
- 删除题库会连带删除其题目、材料、答题记录、复习状态、会话（由 service 在一个事务里完成，不留下孤儿行）；
  题目与题库都是**物理删除**，删掉即不再占用该题库的题号标识。
- 同一题库内按题号标识（`questionKey`）去重：**重复导入同一份题目会跳过已存在的题**（同一 AI 导入任务重复确认、同一份文件导入两次都不会产生重复题或报错）。
- `packageKey` 是跨端/广场的稳定标识；改题库**显示名**不影响已导出的包。
- 复习功能按题库开关：关闭后做题不更新复习状态、详情页不显示复习入口。

## 3. 录题与题型

四种题型（`model/enums/QuestionType.java`，AI 侧同为这四个字符串 `AiImportService.VALID_TYPES`）：

| 题型 | 取值 | 判分方式 | 必填 |
| --- | --- | --- | --- |
| 单选题 | `SINGLE` | 自动判分（选项与答案集合相等） | `options` ≥2、`answerKeys` 非空 |
| 多选题 | `MULTIPLE` | 自动判分（集合相等） | 同上 |
| 判断题 | `JUDGE` | 自动判分 | 答案（正确/错误） |
| 主观题 | `SUBJECTIVE` | **不自动判分**：展示参考答案，用户自评 | `referenceAnswer` 可选，无选项无答案键 |

题目字段（`QuestionFormPanel.vue` 的 13 项脏检查基线）：题干、题型、选项、答案、解析、分类、知识点/主题、分值、题目编号、题号所属卷/部分、材料关联、参考答案、答案来源（`answerSource`）。

**规则**
- 富文本：题干/选项/解析/参考答案中的图片以 `[图片:文件名]` 标记内嵌，渲染时替换为本地图片 URL（详见 `docs/package-format.md`）。
- 主观题允许空答案：选择题若被 AI 判成 `SUBJECTIVE` 但选项齐全，会自动修正为 `SINGLE`；选项为空的"选择题"一律保持 `SUBJECTIVE`（避免"空选项单选"卡住确认导入）。
- AI 补答案（`ai-fill-answers`）只处理非主观题：「有无答案」判断基于 `answerKeys`，因此**主观题不显示"AI 补充答案"标记**（已知取舍）。

## 4. AI 批量导入

流程：`上传文件 → 解析（本地抽取或云端 OCR）→ 分块交给 AI 逐块出题 → 预览校对 → 确认入库`。

- 支持文件：`.txt` `.md` `.markdown` `.csv` `.doc` `.docx` `.pdf` `.xls` `.xlsx` `.ppt` `.pptx` `.png` `.jpg` `.jpeg` `.webp` `.bmp`。
  - 表格（`.csv` `.xls` `.xlsx`）：逐工作表逐行抽出单元格文本（单元格用 ` | ` 连接，多表带 `## 工作表：<名>` 标记）；
    幻灯片（`.ppt` `.pptx`）：逐页抽文本框/表格/备注，带 `## 第 N 页` 标记。
    **只做抽取、不做表头识别或结构化拼装**——列名千奇百怪，本地预先解释反而丢内容（与 PDF 的处理口径一致：抽取原文交给模型）。
  - 老格式（`.doc`）走 POI HWPF 取纯文本；解析失败时提示"另存为 .docx 后重试"。**老 `.doc` 的内嵌图片不提取**（需要图就走 PDF、图片路径，或勾选 MinerU 增强）。
  - **表格与幻灯片里的图片会提取**（2026-09-13，与 docx/PDF 同一套机制，不需要 MinerU）：
    幻灯片逐页取图并按形状顺序就地插 `[图片N]`（整页只有图的纯图片题也保留，同一张图跨页复用只登记一份）；
    Excel 按图片锚定的行（`ClientAnchor.row1`）把 `[图片N]` 插在**该行文本之后**（同一张图锚在两行则两行各一份）。
    图片统一转 PNG（矢量 WMF/EMF 用 POI 渲染）；解不开的跳过并在结果里给出提示。
  - 扫描版 PDF（无文本层）：可配置 **MinerU** 云端解析（设置项 `mineruKey`），或按页渲染成图片交给视觉模型。
    - MinerU 路径也会提取 **Office 文档里的内嵌图**（2026-09-13 修）：PPT 的插图按页归属、无版面坐标时按出现顺序逐张输出；
      Excel 的图片只在 `table` 的单元格 HTML 里以 `<img src="images/…">` 出现，会就地换成 `[图片N]` 锚点——
      锚点落在图片所在的那一行，比 PPT 的页末追加更精准。图片统一转 PNG 后落进 `imports/<jobId>/images/`。
  - 入口位置（2026-09-13 调整）：**拍照/扫描/纯图**（选了 png/jpg/webp/bmp/pdf）时，导入对话框直接给出「MinerU 增强」勾选框；
    其它 MinerU 能受理的格式（doc/docx/ppt/pptx/xls/xlsx）收进**「更多选项」折叠区**，需要时手动开。
  - ⚠️ 可选性只按"格式是否 MinerU 支持"判断，**不再**按"我们是否检测到图片"判断——后者是循环依赖：
    识别失效（老 docx 扫描件、图片型 pptx、矢量图 PDF）恰恰是最需要 MinerU 的时候，却会被自己挡住。
  - 文案口径：**除非导入后发现大量题目缺图，否则不需要开启**（不写"试卷都需要"，因为多数试卷并没有图，会误导）。
    设置页同样把它收进「高级（可选）」折叠区，并在展开后的第一行用加粗句写明这条结论；
    导入预览的素材区底部也给出同样口径的指引（缺图 → 去哪里配置 → 重新导入）。
  - **MinerU 的定位（用户口径，2026-09-13）：识别失效时的最终手段。**
    它要额外注册/额度、走云端、结果质量也不如"直接取原文/原图"，所以**凡是本地能确定性拿到的东西，都不要用它**——
    本地已覆盖 docx / ppt / xlsx / pdf 的取文与取图；只有扫描件（无文本层 PDF）、图片型文档、
    矢量图 PDF 这类本地识别失效的场景，才值得开启。
- 本地解析（`DocumentParserService`，全部离线）：docx 走 POI（按 body 元素顺序，段落与表格交错；提取插图与 MathType 的 WMF/EMF 公式预览图并解码为 PNG），doc 走 POI HWPF（纯文本），xls/xlsx/ppt/pptx 走 POI（纯文本抽取），pdf 走 PDFBox（文本层提取 + 内嵌图片提取 + 按页渲染兜底）。小于阈值的装饰图会被过滤；无法解码的矢量图跳过并给出警告。
- 任务与进度：任务落库，前端通过 SSE（`/ai-import/jobs/{id}/stream`）看进度与日志；任务可删除；`active` 用于应用重启后恢复"进行中的导入"。
- 预览校对（`AiImportPreviewView.vue`）：默认**渲染优先**（直接看题），可切换单题编辑 / 全部编辑；解析出的材料单独成块；图片素材区可预览。
- 确认导入：选择目标题库（可新建）→ 校验 → 写库，临时图片转正到正式图片目录。

**规则**
- 解析出的题目**先不落库**，只有「确认导入」才写入题库；放弃任务即丢弃。
- 题号/卷号冲突（如多个 Part 各自从 1 开始编号）会导致导入数量少于预期，属已知问题，见 `docs/import-issues.md`。
- AI 调用用**你自己的 Key**（BYOK）；本地/内网地址（如 Ollama）允许不填 Key。
- 失败会给出**分类后的原因**（模型超时 / 请求过于频繁 / 无法连接 / 返回内容无法解析 / 文档解析失败 …），并附一段脱敏诊断摘要（凭据替换为 `***`），导入记录页可直接看到；失败码另存于 `ai_import_job.error_code`，供后续做重试策略。

## 4.5 知识点标签（学习路径引擎阶段 0）

题库详情页 →「更多」→「知识点」：把题目对应到**技能图**上的知识点，作为**筛选、配题与讲解**的口径
（设计见 `docs/learning-path-design.md`；字段体系与界面判断见 `docs/question-taxonomy-design.md`）。
**不拿它给用户下"你掌握了没有"的判决**（2026-09-16 收口，见 §4.8）。

- **字段体系（2026-09-15 收敛）**：题目上只有两个分类维度——
  **归属**（DB `topic`，界面文案「试卷 / 章节」＝这题从哪来，自由文本，AI 导入时按原文卷/章标题自动填）
  与**知识点**（技能图节点，多值，受控词表＝这题考什么）。
  旧的「分类」「册数」已从界面下线（DB 列与包格式保留兼容）；
  老题库里只有分类没有归属的题，题库页会出现一次性「把「分类」并入「试卷 / 章节」」提示（只填空值）。
- **技能图**：受控词表（节点 + 前置关系），内置两张官方模板——「公务员行测（通用）」「AI 时代的现代化全栈」；
  节点变更走远端配置通道（不发版），加载时校验悬空前置/重复 id/前置环。
- **词表可以自己改**（2026-09-16 用户反馈："既不能让用户自己编写，又不太准确，应该开放编辑权"）：
  知识点页右上「**管理知识点**」→ `{dataDir}/skill-custom-nodes.json`（只影响本机，不进内容包）：
  - **自定义知识点**：新增（可选所属阶段，默认「自定义知识点」）、**改名**、换阶段、删除。
    **改名不动 nodeId**，所以已经打在这道题上的标签不会失效——这是"自己维护词表"的关键；
  - **官方知识点可停用/恢复**：停用只在本机隐藏（不改官方模板本身，远端模板更新不会冲突）；
    停用时**连其它节点对它的前置引用一起摘掉**，不留悬空前置；
  - 停用/删除后，那些题上的标签变成**失效标签**（如实提示 + 一键清理，见下）；
  - 「**恢复官方模板**」一键撤销这张图上的全部本机改动。
  界面里直接输入新名称仍可即时新建（与"管理知识点"同一份数据）。
  `graphVersion` 随自定义节点与停用记录变化，缓存的分组映射自动失效重算。
- **打标签**：AI 按批提建议（默认逐题判定；题库若填了 `topic` 则优先按组映射，同类题标签天然一致），
  结果落 `question_skill`（`source=ai, confirmed=0`）。**分批推进**：界面一次只花 N 次模型调用，
  可中断可续跑（已处理的题不会重复问模型）。
- **审阅清单（界面主列表）**：以**题**为单位，每题一行 = 题号 + 题型 + 状态 + 题干 + 当前标签（行内多选下拉，
  **就地改、立刻落库**，也可**直接输入新名称新建自定义知识点**）+ 来源（你标注的 / AI 建议 带把握分）+
  行内动作（确认 / 丢弃建议 / 看题干 / 详情）。「看题干」就地展开题干、选项、答案与解析；
  「详情」才跳题目编辑器（可选，不是改标签的必经路径）。
- **筛选与批量**：顶部「全部 / 待确认 / 未匹配 / 已确认」是可点击的计数筛选（不是页签），
  另有知识点筛选（下拉里带题量、直接标出"你没有题"= 缺口，并给一行缺口提示）；
  选择支持「全选本页」与「选中全部 N 题」——后者只把筛选条件发给后端解析（`SkillApplyRequest.filterStatus`），
  几百题也只需一次请求；勾选后可批量设为知识点 / 确认 / 丢弃。
- **口径只允许一套**：`已确认 + 待确认 + 未匹配 = 总题数`（三段互不重叠），
  另单列「可用于判定掌握」= 已确认 **或** AI 置信度 ≥ 0.8 的题数。
  计数与清单由后端**同一份快照**派生（`QuestionTaggingService.snapshot`），
  所以"概览数字"与"清单条数"在结构上不可能对不上（用户实测过 26 vs 16 的口径打架）。
  题目详情（`GET /questions/{id}/skills?templateId=`）与审阅清单**同一口径**：只认当前模板 + 当前图里存在的节点，
  不会把失效节点以原始 id（如 `gk.zl.concept`）显示出来。
- **失效标签**（技能图升级、或删掉自定义节点之后留下的）：读路径一律忽略（不显示、不计入统计与门控），
  但会单独统计（`ReviewPage.orphan`），界面提示「有 N 条旧标签已失效」并可一键清理
  （`POST /banks/{id}/skills/cleanup-orphans`）。
- **动作语义**：`confirm` 确认建议（题级：一次确认这题的全部建议）/ `set` 把这些题的标签设定为给定节点
  （就地改标签、批量设为知识点；写成 `source=user`，会清掉旧的 AI 建议与旧用户标签，反复设置不累积）/
  `retag` 按节点批量改挂 / `reject` 丢弃建议（已确认的标签不动）。
  **返回值统一是"影响到的题数"**（不是标签行数），与界面提示、用户看到的行数一致。
- **标签的用处**：① 按知识点筛题与讲解时说明"这题考什么"；② 配题时挑"你最薄弱的那个知识点"
  （见 §4.7）；③ 复盘的错题分布统计。**没有标签的题照常进练习与复习调度**，缺标签只影响知识点维度的说法。
- 标签与自定义知识点都只存本机；导出题库时随包分发作者确认过的标签，为将来的广场质量分与共享路线做准备。

## 4.6 AI 私教：讲解 / 提示楼梯 / 复盘（学习路径引擎阶段 1）

设计见 `docs/learning-path-design.md` §7.3、§7.4、§9。**五处 AI 调用里的"讲解/追问"与"复盘诊断"就是它。**

入口都只在用户主动开口时才说话（**做题过程绝不自动弹窗**）。**主线是「讲解」，而且它是唯一的解析入口**：

| 入口 | 位置 | 做了什么 |
| --- | --- | --- |
| **讲解（唯一解析入口）** | 成绩报告错题 / 练习历史每题 / 题库列表行内 | 一次讲清三段（边写边显示）：有作答讲「**错在哪**（针对你选的选项）→ **这类题怎么做**（可复用做法）→ **下次防错**（一句能执行的检查）」；没作答或做对了讲「**这道题怎么做** → 这类题怎么做 → **易错点**」。有作答时可以先点错因（看错/蒙的 · 这个知识点不会 · 完全没见过，**可选**）；讲完可就地追问、**存为解析**（进题库）或**存进笔记**（只在本机，见 §4.9） |
| 提示楼梯 | 做题中 · 题目卡右上「提示」 | L1 只指方向 → L2 关键一步 → L3 完整解析；已给过的级别标出来，逐级解锁 |
| 复盘诊断 | 交卷后 · 成绩页顶部「这场复盘」 | 先给**公式统计**（成绩 + 按知识点的错题分布 + 该知识点历史正确率），再点按钮让 AI 讲一遍 |

- **为什么只有一种解析（2026-09-16 用户拍板）**：以前"答错即问"与题库里的"AI 解析"是两套 prompt、两种风格，
  同一道错题会出现两段说法不同的话，而且做完题返回后**再也回不到 AI 讲的那个环节**。现在统一成一个引擎
  （后端 `TutorService.explain`，前端 `QuestionExplain.vue`，三处入口同一个组件）：
  - 口吻由**后端按"这道题最近一次作答对不对"自动判定**（答错 → 错在哪；答对或没作答 → 这道题怎么做），
    调用方也可以显式指定（`mode`）；
  - **回看**：组件挂载时按题拉取上次的讲解（`tutor_message` 已落库），标着"上次讲于 …"直接显示，
    **不再重复花额度**，并把它之后的追问一并带回来；
  - 两个"去处"不是两种解析：**存为解析** = 写进题库（会随包分享）；**存进笔记** = 留给自己的记忆钩子（见 §4.9）。
- **讲解讲的不是通用解析**：上下文里带着「我的作答 / 我的错因 / 这道题错过几次 / 这个知识点上的历史表现」，
  所以能说"你选 B 是因为把基期当成了现期"；官方解析只作参考，prompt 明确要求**讲透为什么，不要照抄**。
- **本应用是"交卷统一判分"**，做题时还不知道对错，所以讲解放在交卷后；做题中给的是**提示**（不剧透答案）。
- **上下文按固定顺序拼**（题干 → 选项 → 正确答案 → 官方解析 → 我的作答 → 错因 → 该题历史 → 该知识点表现 → 最近 4 轮对话），
  既控 token 也让回答有的放矢；掌握度**只以"较弱/一般/较好"描述，不把数值喂给模型**（防止它编造"你的掌握度是 62%"）。
- **薄弱点排序是公式算的**（本场错题按知识点聚合 + 历史正确率），模型只负责把结论讲成人话；复盘 prompt 明确要求
  "只写清单里的题，不要编造"。
- **流式输出**：`POST /api/tutor/{explain|hint|ask|review}` 是 SSE（事件 `session` / `delta` / `done` / `error`），
  边生成边显示；模型网关不支持流式时后端自动降级为一次性返回（体验退化但不失败）。
  讲解的前端按小标题**分块渲染**（两种口吻的标题都在同一张映射表里，按出现位置切块），边写边逐块长出来。
- **落库**：`tutor_session`（含 `self_reason` 错因 —— 比模型猜准得多的第一手数据）与 `tutor_message`
  （助手每条带 `hint_level`，讲解为空）。同一题 + 同一场练习的会话会复用，重新打开能接着上次聊。
- 未配置 AI 时面板给可照做的提示（去设置里填 Key），不影响做题与判分。
- **编辑面板里的"AI 草稿解析"仍走 `POST /questions/ai-analysis-draft`**：那是"录入时按表单内容补一份正式解析"，
  与做题后的讲解不是同一件事；原来的 `POST /questions/{id}/ai-analysis`（按 id 生成一份中性解析）已随统一而退役。

## 4.7 开始练习：配题引擎（隐形）

题库详情页头部只有一个主按钮「开始练习」，点一下直接开练：`GET /api/banks/{id}/practice-plan` 配好题
→ `POST /api/banks/{id}/sessions`（`mode=PLAN` + `questionIds`，顺序即优先级）→ 跳做题页。

**这一层完全不调模型**（零 token）：所有结论都是可复现的公式，同一状态调两次结果完全一样，没配 AI 也能用。
**界面不出现"计划""路线""目标"这些词**，用户看到的永远是「题 + 一句可核对的事实解释」。

- **四个桶按优先级去重**（`PracticePlanService.plan`，同一题只出现一次）：
  ① 错题（最近一次答错，按错过次数从多到少）→ ② 今天到期复习（复习计划开启时；未开启此桶为空且不提"到期"）
  → ③ 薄弱知识点（见下）里**还没做过**的题 → ④ 还没做过的题 → ⑤ 仍不够时挑"最久没做过的"补满。
- **配额**：默认各 30%（`RATIO_WRONG/DUE/WEAK`），剩下给新题；**短练习按优先级保底 1 题**
  （`floor(0.3×1)=0` 曾让"练 1 题"永远只给新题，与"错题优先"的口径自相矛盾）。默认 20 题，上限 200。
- **一词一句都是可核对的事实**：`explain` 只陈述数量——
  「这 20 题：8 题是你之前做错的 · 6 题今天到期复习 · 6 题来自「资料分析·增长」（这个知识点你库里只有 8 题）（题库共 125 题）」。
  **不出现"你应该/建议你/你需要加强/薄弱"**（有测试断言这条）。练习页顶部显示这句，点 ✕ 即可收起。
- **薄弱知识点**：在"你有题、而且还有没做过的题"的节点里挑**掌握度最低**的；掌握度相同（多数是都没做过）
  优先**库里题少**的——那才是真的缺口，而且这个数字能作为事实写进解释里。没有可用标签时就纯按错题/新题配。
- **掌握度公式**（`nodeStates`，设计 §5.2）：`evidence = 对错 × exp(−距今天数/30) × (间隔≥7 天且做对 ? 1.2 : 1)`，
  `mastery = Σ(evidence×w)/Σ(w)`，取最近 8 次作答（近 3 次权重 1.5）。
  **只用于排序与挑题，不展示给用户、不喂给模型、不做"过关/没过关"的判决。**
- **85% 规则**：桶内按 `AdaptiveService.orderByTargetSuccess` 排序，优先"预测成功率落在 80%–90%"的题
  （每题难度按 Elo-lite 从作答记录更新，能力分是掌握度的单调映射，**不落表**）。
- **不落的表**：`user_skill_state` 故意不建——`study_record` + `question_skill` 已是全部证据，
  再存一份就会出现"两份真相"（删掉作答记录后状态对不上）。现算是 O(该题库作答数)，本地数据量下毫秒级。
- **自定义练习**仍然保留（「更多」→「自定义练习…」）：`ALL` / `SEQUENCE` / `TOPIC` / `SKILL` / `REVIEW` / `WRONG` / `FAVORITE`，
  题量与范围自己定；`PLAN` 是"开始练习"用的那一个。

## 4.8 收口记录：从「学习路线」到「开始练习」（2026-09-16）

**背景**：阶段 1–3 做出了学习路线页、目标设定、每日任务、抽测、闪卡。做完发现两个真问题：
① 用户打开题库想要的是"开始练"，路线页把规划与做题拆成两处，得先做一轮元活动（看计划、设目标）才能练
——这是"隔离感"的来源；② 我们本质是题库，没有教学资料与考纲，**没资格判断"你是否已经掌握"**，
一旦宣判错了，整套系统的可信度就归零。

**收口原则**（写下来供以后判断功能去留）：**一个功能如果不能在 3 分钟内让用户感到价值，它就在消耗用户的耐心；
只承诺用户能自己核对的事（错过几次、什么时候到期、这个知识点你有几道题），绝不做掌握度宣判。**

- **界面上撤掉的**：学习路线页、目标与题量设定、每日任务清单、抽测（及"抽测掉下来了"）、闪卡页。
  入口一并下线：题库头部的「学习路线」「闪卡」按钮已删除，路由与 E2E 脚本同步删除。
- **保留在后台的引擎**（不再有界面，但配题/复习调度仍然用它们）：
  掌握度公式与缺口统计（用于挑薄弱知识点）、**85% 难度规则**（`AdaptiveService.orderByTargetSuccess`，
  配题桶内排序与难度初值都走它）、间隔重复调度、AI 私教（讲解/提示/追问/复盘）。
  2026-09-16 审计纠偏两处**文档承诺与代码不符**的地方：`interleaveRatio`（交错混练）**从未接入**配题；
  `CardService`（闪卡）**没有任何生产调用方**，是纯测试资产。
  相关表（`card`、`question_difficulty`、`daily_task`、`learner_profile`、`practice_session.scope_node`）
  以及 `skill_node`/`skill_edge` **保留不删**：删表要做迁移、有丢数据的风险，而留着的成本只是几个空表；
  将来若要接"广场上的路线模板"可以复用（`skill_node`/`skill_edge` 的**写入口**已随审计删除——它们从来没被读过）。
- **知识点的定位下调**：从"判定掌握的地基"变成**筛选与讲解的维度**（见 §4.5）——
  标签只为"按知识点筛题 / 说清这题考什么 / 挑最该补的点"服务，不再要求用户先把标签确认齐才算数。
- **下一步的投入方向**（按价值排序）：① 错题讲解做到最好（本轮已完成，见 §4.6）；
  ② 缺口补题（按缺口用 AI 出题 → 预览确认入库）；③ AI 导入继续打磨；④ 广场的质量信号
  （题库/标签/路线模板分享）。
- 产品口径的长期答案：**学习路线的可信度不靠自己造，靠"谁给的"**——
  将来由名师/机构在广场提供路线模板，我们只做执行器，并把"覆盖清单（事实）"而不是"时间表"给用户。

## 4.9 笔记（我的，不是题库的）

入口：侧边栏「**笔记**」（顶层页 `/notes`）；题库详情「更多」→「我的笔记」进的是同一页、只筛这个题库；
做题报告与练习历史里**每题**也有「记一笔」；AI 讲解下面的「**存进笔记**」把整段讲解存进来（`source=ai`，列表里标出来）。

**边界（这一节存在的意义就是把边界写死，别让两个功能互相蚕食）**：

| | 解析 | 笔记 |
| --- | --- | --- |
| 属于谁 | **题库的**（`question.analysis`） | **我的**（`note` 表） |
| 会不会给别人看 | 会：随题库文件导出、发布到广场 | **不会**：只存本机，不进内容包 |
| 谁写的 | AI 生成 + 人工校对 | 我自己（或从讲解一键存） |
| 用途 | 让题库更完整（复利） | 我的记忆钩子、体会、老师的话 |

- **归属是关联，不是字段**（`note_link`）：笔记自己不隶属于任何题库/题目，一条笔记可以同时挂在
  **多个题库、多道题**上，也可以一个都不挂（未归类）。列表按最近更新排序，关联标签可点着跳回去，也可就地解除。
- **"这个题库的笔记"口径**：挂在库上的 **或** 挂在这个库某道题上的（列表与计数同一处实现）。
- **删库/删题只删关联，不删笔记**：用户写下的东西不该因为题库被删就消失，它会变成"未归类"留在笔记页。
- **纯文本**：上限 2000 字（超长截断而不是报错），渲染与编辑用同一套规则（公式/图片能正常显示）。
  **刻意不做层级/标签**——那会变成第二个文档编辑器，而这里要的是"随手记一句"。
- **不进内容包**：`ContentPackageService` 不管笔记；备份恢复按"整个数据目录"走，所以备份里**会有**（本机数据完整性优先）。

## 5. 做题、判分与错题

会话模式（`PracticeSessionService.normalizeMode`）：`PLAN`（按配题结果，见 §4.7）/ `ALL`（整库未做优先）/ `SEQUENCE`（按题号顺序，可指定起点）/ `TOPIC`（按试卷章节）/ `SKILL`（按知识点）/ `REVIEW`（到期待复习）/ `WRONG`（错题）/ `FAVORITE`（收藏）。

- `PLAN` 由「开始练习」使用：`questionIds` 原样练、顺序即优先级、忽略 `count`
  （题数由配题引擎决定，保证"解释里说 20 题"和"实际练 20 题"一致）；重复/不存在的 id 会被丢弃而不是报错。
- `SEQUENCE` 是唯一支持 `startQuestionId` 的模式。
- 材料题按材料分组为"单元"（`buildUnits`）：同材料的多道小题在会话中连续出现。
- 附加筛选 `scope`：`favorite` / `wrong` / `undone`。

判分与自评：
- 客观题提交即判分（`correct`）。
- 主观题：用户写答案（`userAnswer` 必填）→ 展示参考答案 → 自评 `CORRECT` / `PARTIAL` / `WRONG`；实得分 = 满分 / 半分 / 0（`StudyRecordService.earnedScore`）。

**错题口径（全局统一，务必遵守）**
> 一道题"**最近一次作答为错**"才算错题；历史答错但最近已答对的题**不算**。主观题自评 `PARTIAL`/`WRONG` 算错（此时 `is_correct` 为 null，不能只看该列）；**未自评不算错**。
> 实现：**统一在 `StudyRecordService.isWrong / isCorrect / effectiveGrade` 三个静态方法里**，配题、错题本、会话 `WRONG`、
> 题目列表 `scope=wrong`、导出范围 `wrong`、统计页的错题治愈、讲解口吻判定、能力分**全部**调它。
> 2026-09-16 审计发现这条规则曾被复制成 5 份且互不相等（统计页与错题本的口径相反、"未判定"在会话页被算作答错），
> 已合并，并由 `WrongAnswerRuleConsistencyTest` 用同一批数据把五个出口钉在一起。

**复习算法（简化间隔重复，`updateReviewState`）**
- 每个"题目"维护一条复习状态（`review_state`：`level`、`interval_days`、`due_at`、`suspended`）。
- 答对：`level = min(level+1, 5)`，间隔 `= min(2^level, 30)` 天 → 实际序列 `1→2→4→8→16→30` 天封顶。
- 答错：`level = 0`，间隔 1 天，`due_at = now`（立即可复习）。
- 可对单题「暂停复习」（`suspended`），可一键重置某题库全部复习进度。
- 复习汇总（待复习数、已过期天数 `overdueDays`）供详情页与统计页使用。

## 6. 统计

- 总览（`StatsSummaryResponse`）：总题数、已答、已判定、正确数/正确率、待复习、连续天数等 + 每日明细（日期、作答数、判定数、正确数）。
- 明细（`StatsDetailResponse`）：题库维度统计（`BankStat`：总量/已答/已判定/正确）+ 会话维度统计（`SessionStat`：模式、题数、正确率、耗时）。
- 设计原则（页面副标题即产品意图）："每个数字都指向下一步（去做题 / 去复习）"——统计页的每个数字都能点击跳到对应动作。

## 7. 打印试卷

- 独立路由 `/banks/:id/print`（无侧栏，固定布局），入口在题库详情。
- 两个版本：**纯题目**（学生作答）/ **带答案 + 解析**（教师核对）；范围与分类筛选即时生效。
- 用浏览器打印（`window.print()`），可选「另存为 PDF」导出 PDF；打印样式在 `.print-page` 的 `@media print` 中定义。

## 8. 内容包与本地作品

- 导出：`POST /api/banks/{id}/export`（JSON）、`POST /api/banks/{id}/export-tiku`（`.zip` 题库压缩包）。
- 本地作品页的「导出文件」：`POST /api/exports/export` 直接写入目标目录，文件名 `{题库名或packageKey}-{版本}.zip`（清理 Windows 非法字符，同名覆盖以最新为准），并落一条导出记录。
- 默认导出目录：`文档\拾题`，用户改过之后记住（`{数据目录}/export-prefs.json`）。
- 版本号自增：解析当前版本后补丁号 +1（`1.2` → `1.2.1`；无法解析 → `1.0.0`）。
- 导出记录可删除；发布成功后标记「已发布」（`mark-published`）。
- `/api/exports/**` **不需要登录**（纯本地数据）；`/api/center/publish*` 需要登录。

格式细节（容器结构、字段表、校验规则）见 **`docs/package-format.md`**——那是跨端契约，改动必须两端同步。

## 9. 广场与账号

- 客户端能力：浏览/搜索题库、看作者主页、收藏、评论/回复/点赞、关注作者、下载并导入（"导入"直接把广场包的题目写进本地题库）。
  - 广场导入会在应用内显示进度（下载 + 写库都在后端同步完成，慢网要等一会儿）；下载读超时 3 分钟，
    超时/失败会明确说明"网络较慢或文件较大，可先用浏览器下载该文件，再在题库页点「导入」选择本地文件"。
- 作者能力（"我的作品"）：发布新版本、修改版本说明、替换包文件、下架、查看下载/收藏/评论数。
- 桌面端登录：应用内直接用账号密码或 GitHub 登录广场，token 保存在 `{数据目录}/center-auth.json`；请求以 `Authorization: Bearer` 转发。
- 官网（浏览器）：cookie 会话（`pickq_session`）+ 人机验证（Cloudflare Turnstile）。
  - 官网文件下载（`web/server/api/packs/[packageKey]/[version]/file.get.ts`）会返回 `Content-Length` 与 `Accept-Ranges`，
    并支持 `Range` 请求（206 / 416）：浏览器能显示**真实下载进度**，中断后可**断点续传**；
    页面在下载按钮下方给出"卡住了怎么办"（复制直链 / 重新下载）。此前没有文件大小信息，只能干等且中断就得从头再来。
- 权限：普通用户 / 管理员（由服务器环境变量 `ADMIN_USERNAMES` 指定），管理员可进后台管理用户与题库。
- 内容治理：举报与下架流程由官网侧实现（`removal.ts`）。

**规则**
- 一个账号在桌面端与官网是同一账号，登录任一即可管理自己的作品。
- 发布是"先导出为 `.zip` 再上传"的两步：导出 → 校验（inspect）→ 上传 → 标记已发布。失败不会影响本地题库。

## 10. AI 配置

三层结构：
1. **内置模板**（前端常量）：DeepSeek、OpenAI、Anthropic、Gemini、通义千问、Kimi、Groq、Mistral、智谱、本地 Ollama 等。
2. **远端预置目录**：`https://pickq.cn/config/ai-presets.json`（服务器 `/opt/pickq/config/`，**与站点部署解耦，改文件即时生效**），客户端经本地后端 `GET /api/ai/presets`（内存缓存 1 小时）取回并按名称合并；远端可显式用空字符串覆盖内置项。
3. **动态模型列表**：`POST /api/ai/models` 探测候选接口（`{base}/models` → `{base}/v1/models` → 本地 `/api/tags`），Anthropic 用 `x-api-key` + `anthropic-version`。
- 弃用自愈：远端 `deprecated[]` 给出旧模型 → 新模型的映射与提示，前端 `utils/aiModelHelp.js` 在用户选中废弃模型时给出替换建议。
- 连通性测试：`POST /api/ai/settings/test`；Key 只回显掩码。

**规则**
- 必须有 `baseUrl` + `model` 才算配置完成；**公网地址必须填 Key，本地/内网地址可以留空**（`NetAddress.isLocalOrPrivate`：`localhost`/`::1`/`127.0.0.0/8`/`10/8`/`172.16-31`/`192.168/16`），留空时请求不带 Authorization 头。
- AI 调用与文档解析都在本机进行；除你配置的模型服务外，不上传任何内容。

## 11. 备份与恢复

- 完整备份：数据库 + 图片 + 配置，生成一个备份文件（用户选择保存位置）。
- 恢复：`POST /api/backup/restore-prepare` 准备恢复 → 壳负责退出应用、替换数据目录、重启（因此恢复过程中会看到应用自动关闭并重新打开）。
- 学习记录可单独导出/导入 JSON（`/api/study-records/export|import`），用于跨机器迁移刷题进度。

## 12. 外观、语言与更新

- 主题：浅色/深色（设置页「外观与语言」）；界面语言：简体中文 / English，**组件级字典**（每个 `.vue` 自带 `zh-CN`/`en-US` 两份文案），命名插值用 `{n}` 风格。
- 更新：检查 `https://pickq.cn/updates/latest.json` → 下载（可取消，取消后对话框立即关闭并提示"已取消下载"）→ SHA 校验 → 安装。GitHub Releases 作为镜像/备用渠道。
- 更新公告（Release 说明）**只写用户可感知的功能变化**，不写安全与运维细节——这条是硬约定，见 `docs/release-notes-guide.md`。

## 13. 明确不做 / 已知边界

- 不做云端同步：题库与做题数据默认只在本机；跨设备靠 `.zip` 题库文件与广场。
- 不做账号强绑定：不登录也能用全部本地功能。
- 不做移动端网页版：手机端计划是独立原生应用（见 `docs/design-mobile.md`）。
- **不做教学与学习路线宣判**（2026-09-16 收口，见 §4.8）：我们只有题目和作答记录，没有教材、考纲与课程，
  所以不给"你今天该学什么 / 你是否已经掌握 / 你多久能学会"这类结论；
  只给可核对的量（错过几次、什么时候到期、这个知识点你有几道题）与"下一步练哪几题"。
- **不做第二套解析**（2026-09-16 统一，见 §4.6）：同一道题只有一种讲解口吻（按有无作答自动切换），
  两个去处是"写进题库"与"写进我的笔记"——不再有"另一种风格的 AI 解析"。
- 已知问题清单（导入解析、题号冲突等）见 `docs/import-issues.md`。
